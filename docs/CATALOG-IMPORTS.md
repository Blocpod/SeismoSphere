# Durable historical catalog imports

Research → Historical catalog starts a persistent job. Choose USGS or EMSC, an elapsed interval from 1900 onward (up to 50 years), a minimum magnitude, and global or regional rectangle scope. West > east wraps across the dateline. Pause and Resume retain completed chunks. Cancel ends the job without deleting observations. Closing a browser has no effect on the job; unfinished running jobs resume when the backend restarts. Explicitly paused jobs remain paused.

One sequential queue uses the existing SQLite store and Node fetch/AbortController. Requests span at most 31 days. Dense intervals are bisected when the provider reports its result cap; no capped response is accepted as coverage. Temporary network/408/429/5xx failures receive up to four attempts with exponential delay and Retry-After support (bounded to one day). Other failures stop at the first unfinished interval for inspection and manual resume. A request has a 45-second timeout and an 80 MB response-body limit. No new dependency or external queue service is required.

The [USGS FDSN documentation](https://earthquake.usgs.gov/fdsnws/event/1/) specifies inclusive start/end times, a 20,000-event result limit and query ordering. Adjacent chunks share their endpoint; provider IDs and unchanged revisions prevent duplicate insertion. Invalid or out-of-range records stop the chunk and are retained in its failure receipt. Empty HTTP 204 intervals are valid zero-result responses. EMSC requires `format=json`, whereas USGS uses `format=geojson`. Its GeoJSON-shaped payload uses ISO origin/update timestamps and a separate positive depth property; its geometry Z is negative depth. The adapter preserves original timestamps, source identifiers, magnitude scale and ISF event type. Unknown event types remain unknown; known/suspected non-earthquake types cannot enter earthquake-only models. Suspected earthquakes retain their explicit certainty label. See the [EMSC service documentation](https://www.seismicportal.eu/fdsn-wsevent.html), [EMSC field specification](https://www.emsc-csem.org/Files/epos/specifications/Specs_fdsnevent-WS.pdf) and [ISC event codes](https://www.isc.ac.uk/standards/isf/).

## Integrity and meaning

Each successful chunk commits observations, an immutable receipt, job progress and coverage in one SQLite transaction. Receipt JSON includes query URL, interval, reception time, response-text SHA-256, row count and inserted revisions. A failed transaction advances none of these. Failed HTTP/validation receipts remain inspectable; canceled in-flight requests do not imply a completed response. Receipt sequence allocation reads the database so an interruption between a failed receipt and its progress update cannot reuse its identifier.

Coverage describes a successfully retrieved query interval at a specified provider and magnitude threshold. **It does not establish detection completeness, homogeneous magnitude scales, or what an operator knew historically.** Imported revisions receive their actual local reception time. Strict historical replay therefore does not backdate this archive. Revised-catalog replay can use it with that distinction visible.

Coverage checks join contiguous or overlapping intervals only for the same provider and a sufficiently low magnitude threshold. Even a one-millisecond gap fails coverage. Every retained segment must also spatially contain the requested rectangle. Regional coverage cannot satisfy a global request; adjacent partial spatial tiles are not unioned. Both providers support dateline rectangles through native longitude wrapping. Temporal/spatial ETAS checks use the required regional bounds. Historical coverage is retained separately from the rolling live-feed history.

Receipts download from each job card. `POST /api/import` returns HTTP 202 and a job identifier; `GET /api/import-jobs` supplies current summaries and the actual active job ID. `POST /api/import-control` accepts `id` and `action` (`pause`, `resume`, `cancel`). `GET /api/import-export?id=…` exports the job and receipts. Existing origin/authentication and viewer restrictions apply. The previous synchronous import endpoint behavior has been replaced.

## Verification

`test/imports.test.mjs` exercises pause/restart recovery, deduplication, immutable receipts, splitting, retry, invalid responses, transaction rollback and coverage gaps using the existing Node test runner. `scripts/import-check.mjs` exercises real USGS imports through Chrome and WebKit, including pause, reload, resume, receipt download and 320/390/768-width layouts. It starts or reuses the 2000-01-01 through 2026-01-01 M≥5 USGS archive job; it does not start duplicate active imports.

The actual backend restart retained 60 committed chunks and identical receipt hashes before automatically resuming. The 2000–2025 archive subsequently completed with 307 chunks and 46,522 received rows, exactly matching a fresh USGS count query. A separate nine-chunk job filled 2026 through September 13, receiving 1,403 rows and inserting 1,264 revisions. Historical Sumatra replay shows M9.1; strict 2004 replay remains empty. Detailed job IDs and verification evidence are recorded in the build status. This archive is the foundation for broader replay and model training; it is not itself a trained discovery model.

Regional verification: Japan 2010–2011 M≥2 completed 24 chunks with 5,474 received rows and 4,617 new revisions (job `7109245f-7387-4423-8989-4efef5317897`). An actual EMSC dateline job, `89964ac9-cff0-4e9c-95f8-063b4f78da4f`, retrieved 25 records for 2026-09-01T00:00Z through 2026-09-08T00:00Z, M≥4, 35–10°S and 170°E–170°W. The first retained Fiji event has depth 547 km, mb 4.8 and its original fractional ISO timestamps. Date-only provider queries can interpret an endpoint differently, so count comparisons must use identical explicit UTC times. Regional completeness analysis is documented in [CATALOG-COMPLETENESS.md](CATALOG-COMPLETENESS.md).
