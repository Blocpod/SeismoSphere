# Catalog event-coverage reviews

Research lab → Saved backtests → Review event coverage evaluates the first selected saved experiment. Select a magnitude floor before running. It requires complete retained catalog retrieval coverage for that experiment's interval and region at the chosen floor; this does not establish detection completeness.

The domain is `(experiment start, experiment end]`, global or the saved target-center rectangle. Only active earthquakes from the experiment's provider are included. The entire interval contributes to the denominator, including gaps with no alerts. For each engine, a catalog identity is covered if at least one saved forecast contains its location, event time and magnitude. Events at the exact forecast start, triggering-source identities and aliases are not detections. Overlapping forecasts count an event only once. A forecast can cover several earthquakes. The UI lists the first 100 missed events per engine; the export retains all matches and missed IDs.

Event recall is covered events / eligible events, or unavailable if there are no eligible events. Its denominator is the retained catalog population, not all earthquakes in nature. Empty-forecast fraction is forecasts with no eligible full-envelope event / forecasts, or unavailable with no forecasts. These denominators differ. No true-negative space-time partition is defined, so this workflow does not calculate false-positive rate or F1. Standard recall denominator reference: [scikit-learn metric documentation](https://scikit-learn.org/1.5/modules/generated/sklearn.metrics.recall_score.html).

These are retrospective, threshold-dependent descriptive reviews of revised catalog data. They are separate from original frozen backtest scores and from prospective protocols. Regional reviews restrict outcomes to the region even when a forecast circle extends beyond it. Forecast magnitude ceilings still apply. The UI's original hit counts can therefore differ from these counts. Dependence from aftershocks, overlapping windows and target selection prevents interpreting these counts as independent-trial significance or validated prospective skill.

Each review retains its experiment summary, exact forecast bodies and hashes, catalog events, coverage records, evaluator/geometry source and chosen domain. The input content hash identifies the review; the result has a separate SHA-256. SQLite blocks updates and deletions. Repeating identical inputs reopens the existing review. Revised inputs create a new review. The Saved event-coverage review selector lists prior reviews for the first selected experiment by time, magnitude floor and event count. Reopening checks stored evidence hashes and restores the original threshold and result without accessing the current catalog or running another assessment. Earlier evidence URLs remain usable. Late responses are discarded after changing the review, experiment or threshold. No code from an export is executed. Evaluation is bounded to 25 million event/forecast comparisons.

## Acceptance

The existing 2011-02-15 through 2011-03-25 global experiment, reviewed at M ≥ 4.5, contains 2,367 eligible catalog earthquakes. DS covers 160 and misses 2,207 (71 empty forecasts of 94); recent-rate covers 1,051 and misses 1,316 (41/94 empty); null covers 12 and misses 2,355 (82/94 empty). A separate Python haversine/matching calculation reproduces all covered/missed sets and empty counts. This is a software check, not independent validation of the catalog or scientific model.

Focused tests cover dateline regions, overlapping alerts, gaps, boundaries, source aliases, duplicate identity rejection, deleted/provider-excluded events, missing denominators, retrieval coverage, immutability and revision separation. The complete regression suite passes 129 tests. Actual desktop UI creation, immutable reuse and exported evidence were inspected. No forecasts were issued; the existing 282-record ledger and its head hash are unchanged.

## Offline reproduction

Run `node scripts/reproduce-detection.mjs PATH_TO_EXPORTED_JSON` from the project. The checker verifies the input/result hashes, exact local numerical evaluator and geographic code, experiment domain and forecast membership, then reproduces the full report including all matched and missed event IDs. Storage/history-only changes do not invalidate the numerical implementation check. Embedded code is never executed. Altered reports, experiment scope, forecast sets and evaluator source are rejected even when their content hashes have been recomputed.

The actual retained 2,367-event 2011 review reproduces identically. This check establishes internal numerical reproducibility; it does not authenticate upstream catalog retrieval, forecast issuance or timestamps. Use the full ledger evidence to check the forecast chain.
