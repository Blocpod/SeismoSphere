# Scientific presentation

Use **Scientific** at the start of the Earth toolbar to switch between scientific and cinematic rendering. The choice is saved in this browser. The copilot also accepts explicit commands such as **Use scientific view**, **Turn off cinematic effects**, and **Restore cinematic view**. Questions about scientific validity do not switch modes.

Scientific mode uses the existing day-image composite with an unlit Three.js `MeshBasicMaterial`. It removes the night-light shader, normal-map/specular lighting, cloud shell, atmospheric rim, halo and stars. Earthquake, forecast and selected-section sprites become solid discs with ordinary alpha compositing; the derived field uses ordinary compositing as well. Cloned surface-marker textures are identified through their shared source, so projected events cannot retain the cinematic glow. Marker position, magnitude sizing, depth colors, age opacity and analytical layer selections are retained.

Automatic orbit and camera easing are disabled. Focus changes are immediate; path exploration advances only through **Next stop**. Manual rotation and zoom remain available. Switching back restores cinematic shading and sprite blending without automatically starting an orbit. The active flight ends when scientific mode is enabled.

The same observations, candidate forecasts, model scores and cutoff remain in use. Scientific presentation does not validate a forecast, convert model match into probability, authenticate the illustrative route graph, or turn composite imagery into a terrain measurement. The user can still independently show or hide hypothesis layers. X-ray, Slab2 and oblique cutaway work in both modes; switching mode preserves material clipping and transparency, and leaving a cutaway cannot restore clouds in scientific mode.

PNG/SVG publication figures use the selected mode. Their matching JSON includes the actual material type and cloud/atmosphere/halo/star visibility, marker representation, lighting description and automatic-motion policy. SVG captions identify scientific rendering and retain all existing source and model disclosures. The existing [figure export](FIGURE-EXPORT.md) and [camera travel](CAMERA-TRAVEL.md) instructions still apply.

## Verification and remaining device work

`scripts/scientific-check.mjs` exercises the actual application in Chrome and WebKit: all 959 events in the selected 2011 replay and candidate identifiers stay unchanged across the mode switch, all 18 marker materials use solid discs, clipping survives scientific/cinematic changes inside a cutaway, manual path steps work, preferences survive reload and figure evidence hashes match. It checks toolbar access at phone, tablet and laptop widths and checks visible ocean pixels in fresh portrait/landscape mobile screenshots. `scripts/presentation-ai-check.mjs` verifies actual default Qwen command execution through the UI and an authenticated Astra response. `node --test` passes 43 tests, including explicit/negated presentation commands.

**Installed WebKit resize limitation:** the Windows Playwright WebKit 26.5 runtime loses visible WebGL compositing after a desktop-to-mobile resize, even though the GPU still renders valid pixels. A standalone WebGL2 page with a continuously red canvas over a blue HTML background reproduces it without Three.js or application code: the initial screenshot is red and the resized screenshot is blue. Run `node scripts/webkit-resize-check.mjs` for the retained reproduction and report. Neither waiting for more frames nor preserving the drawing buffer corrected the runtime behavior. No speculative workaround was added to the application.

Fresh mobile-sized WebKit pages and Chrome's resize flow are tested separately. WebKit resizing is **not accepted**, and viewport emulation is not physical iOS/Android acceptance. Real Safari/device testing and the overall visual-quality target remain open. This mode fulfills the brief's cinematic-effects toggle; it does not complete the full platform.
